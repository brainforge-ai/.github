# Contributing

Thanks for taking a look. A few ground rules keep the public repositories useful.

## Issues

Bug reports and feature requests are welcome on any public repository. Use the issue templates and include the version you ran.

## Pull requests

Open an issue first unless the change is small and obvious, such as a typo or a broken link. We will tell you whether a pull request fits the roadmap before you spend time on it.

Do not open pull requests against the hiring assessment or challenge repositories. Those repositories are not open to unsolicited contributions.

## What we look for

- One change per pull request.
- A description of the problem and the effect of the change.
- Evidence that the change works. For a check, include the query and the expected finding.
- No secrets, tokens, customer data, or real warehouse output.
- No new third-party dependency without a reason.

## Licensing

By contributing, you agree that your contribution is licensed under the repository's license. Vendored third-party content must keep its original license and attribution.

## Security

Do not report vulnerabilities in a public issue. See [SECURITY.md](SECURITY.md).
